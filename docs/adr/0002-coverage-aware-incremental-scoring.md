# 使用知识库覆盖证据驱动三类增量价值评分

新闻代理不再沿用 Hype、Facts、Signal，而是分别评估游戏设计方法、创作与生产工具、内容参考与储备三类增量价值。评估以 `my-wiki` 的分层覆盖和近邻证据为依据，由 durable Agent 准备证据、JEV 执行概率化判断；用户通过自然语言反馈修正分类与数值，后续评判使用成对示例并统计分类漏标、多标、MAE 和 Bias，不自动偏移分数或修改评分规则。

## 决策

### 分离证据准备与 JEV 判断

JEV 不直接检索知识库。durable Agent 负责理解材料、提取少量核心知识主张、规划查询、选择候选并阅读近邻上下文；检索和文件读取由工具执行。JEV 只接收整理后的材料、主张、证据、查询回执和相关校准示例。

禁止提供一个同时隐藏检索与评分的 `getNoveltyScore(url)` 黑盒。必须能够分别诊断检索遗漏、覆盖判断错误与价值判断错误。

### 工具契约

- `lookupMaterial(canonicalUrl)`：精确查找同一材料在 wiki、synthesis、raw 和 bookmark 中的记录。
- `searchCoverage(claimId, queries, scopes)`：围绕单条主张执行中英文、别名和结构词检索，返回候选、实际查询词、实际目录范围与失败信息。召回分数只用于安排阅读顺序，不表示覆盖程度。
- `readCoverageEvidence(claimId, paths)`：读取足够支持判断的原文上下文，返回稳定的证据 ID、路径、覆盖层、摘录和内容哈希；不可读路径单独报告。
- 材料读取工具在依据不足时补充全文、字幕或转写，并标明实际阅读深度。
- `assessIncremental(material, claims, coverage, calibrationExamples)`：在固定证据快照上执行 JEV，不让 JEV 编造证据路径或查询范围。

工具层固定关联主张 ID、证据 ID 和检索回执。JEV 的 state 只包含必要的近邻证据，不转储整个知识库。

### JEV 问题结构

- 使用三个独立 `noul` 判断材料是否适用于游戏设计方法、创作与生产工具、内容参考与储备，不强迫单分类。
- 对每条核心主张使用 `choice` 判断 `covered`、`partial`、`not_covered` 或 `unknown`。检索失败和依据不足必须归为 `unknown`，不能当成未覆盖。
- 分别使用 `score` 评价新增程度与创作价值，再形成三类创作输入的 0–100 增量价值；保留概率分布、置信度和证据关联。
- 优先使用同主题、同来源或同类覆盖情形的用户修正示例，不只使用最近反馈。

### 模型与工具边界

主评分管线包含两个显式模型阶段：

1. **证据准备 Agent**：提取主张、生成检索词、选择候选并判断需要阅读的相关上下文。
2. **JEV 裁判**：基于固定证据执行覆盖、适用性和价值判断。

canonical URL 规范化与精确查重、实际搜索调用、文件读取、哈希、版本记录、数值换算和持久化由普通工具完成。`obsidian_search` 对编排层是工具，其底层是否使用嵌入或其他模型由该工具实现决定，不宣称整个检索过程没有模型。视频转写等按需能力也可能调用额外模型。

自然语言评分反馈是独立的按需模型交互，不属于每次新闻评分管线。明确的用户修正由 Agent 直接保存并回显，模糊表述先追问；Agent 不修改评分 Prompt 或阈值。

### 评分快照

覆盖快照使用 `HEAD` 加三个覆盖目录内已跟踪及未忽略未跟踪文件的内容哈希，每批计算一次并复用。每次评估绑定材料内容哈希、实际阅读深度、JEV 命令版本、知识库覆盖快照和证据集合。上述输入变化后才重新评估；评估失败记为未知，不当作零分。界面区分待评估、已有评分和覆盖依据不足；低置信度评分保留数值并说明原因，用户可请求 Agent 补充阅读或重新检查。待评估卡片先按发现时间与相关性排列；评分完成只更新当前卡片，不立即重排，下次刷新或采集再使用正式分数排序。

## Considered Options

- 沿用 HFS 并替换关键词：无法表达相对于个人知识库覆盖的增量价值。
- 只使用单一重要性分数：会丢失一篇材料在不同创作输入类型下的独立价值。
- 让 JEV 直接读取整个知识库：上下文预算有限，且无法审计检索遗漏。
- 只提取主张后用工具自动评分：无法可靠完成语义查询规划、证据适用性阅读和概率化价值判断。
- 自动偏差校正或自动修改 Prompt：样本少且覆盖状态持续变化，容易隐藏评分问题。

## Consequences

材料通过相关性与去重后先以待评估状态进入实时 Feed，覆盖评估在后台执行并通过 SSE 更新卡片，不阻塞整批采集；正式增量价值用于后续排序，低分不直接过滤材料，也不自动触发 Bookmark。评分记录需要同时保留覆盖证据、查询回执、阅读深度、规则版本、模型原值和用户修正值；检索遗漏与价值判断错误必须分开处理。
