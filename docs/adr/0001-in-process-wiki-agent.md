# 通过进程内 Pi SDK 委派知识库 Agent

> 范围调整：当前版本的 Bookmark 只进入待收藏列表，不实施后续委派。本文仅保留后续架构方向；只读覆盖评估仍可用于增量评分。

新闻代理与 `my-wiki` 在同一台机器运行。新闻服务端通过 Pi SDK 在以 `my-wiki` 为工作目录的会话中调用知识库 Agent，由它提供只读的批量覆盖评估，并在用户确认 Bookmark 后执行来源登记、查重和治理校验；新闻代理不直接写入知识库 Markdown。

## Considered Options

- Pi RPC 子进程：具有进程隔离，但需要额外管理进程生命周期、事件流和重连。
- 本地 HTTP 服务：适合跨设备部署，但同机场景会引入不必要的鉴权和服务管理。
- 新闻代理直接检索或写入文件：会绕过或复制 `my-wiki` 的检索语义与写入治理。

## Consequences

知识库 Agent 的覆盖评估与 Bookmark 写入必须采用不同的工具权限。持久任务需要保存委派请求与结果，并在崩溃恢复时先核对知识库现状，避免重复登记；后续若支持跨设备部署，需要重新评估传输边界。
